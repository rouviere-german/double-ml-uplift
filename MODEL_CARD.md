# Model card: retention-offer uplift engine

Format after Mitchell et al., "Model Cards for Model Reporting" (FAT* 2019). Every number below
is copied from output this repository actually produced, with the command that produced it.

This card describes two things that are usually documented separately, because here they cannot
be: a **set of estimators** and the **assumptions under which their output means anything**. A
CATE model with a good PEHE and a false causal assumption is worse than no model, because it
produces confident targeting decisions in the wrong direction.

## Model details

- **Name and version:** `double-ml-uplift` 0.1.0
- **Type:** cross-fitted double/debiased machine learning for a binary treatment. Nuisances are
  LightGBM (default), ridge/logistic, or OLS/linear-probability; the conditional-effect model is
  Kennedy's DR-learner — an AIPW pseudo-outcome regressed on the covariates, both stages
  cross-fitted.
- **Owner:** Rouviere German
- **Date:** 2026-09-21
- **Licence:** MIT (code). All data is generated by the bundled simulator.
- **Artifact format:** LightGBM text dumps and JSON coefficient documents, each carrying its
  SHA-256 and verified on load. Never pickle.
- **Reproducibility record:** every estimate stores the specification SHA-256, the estimation
  configuration SHA-256, a dataset digest over `(unit ids, features, treatment, outcome)`, and
  the fold-assignment digest. Folds are `blake2b(customer_id, key=salt) mod k`, so the same
  customer lands in the same fold across reruns, row orders and subsets.

## Intended use

- **Primary use:** estimating the average and conditional effect of a retention offer on retained
  revenue from historical campaign data, and ranking customers for a budget-constrained campaign
  when — and only when — the declared causal graph identifies that effect and the data supports it.
- **Intended users:** analysts who can write down the causal assumptions and are prepared to have
  them refused; operators who release targeting lists under approval.
- **Out-of-scope uses:** continuous, multi-valued or dynamic treatments; multiple time points;
  survival or time-to-event outcomes; instrumental-variable, regression-discontinuity,
  difference-in-differences or mediation designs; any use where the DAG cannot be written down;
  any use on real customer data without the data-governance work this repository does not do.

## The assumptions, stated plainly

The estimates are valid if and only if:

1. **The declared DAG is correct** in the respects that matter — no missing edge into both the
   treatment and the outcome, and no adjustment variable that is actually post-treatment.
2. **Unconfoundedness given the adjustment set:** `(Y0, Y1) ⟂ T | Z`.
3. **Positivity:** `0 < P(T = 1 | Z) < 1` for every customer in the population.
4. **SUTVA:** one version of the treatment, and no interference between customers.
5. **Rows are independent.** Influence-function standard errors and the multiplier bootstrap both
   assume it; clustered or panel data would need different variance estimates.

What the tool does about each:

| Assumption | What is checked | What is not |
|---|---|---|
| 1. DAG correct | Structural sense: acyclicity, a directed path from treatment to outcome, declared roles that agree with the graph, no post-treatment variable in the adjustment set. Identification decides whether the graph as declared identifies the effect | The tool **never discovers the graph**. A missing edge is consistent and invisible |
| 2. Unconfoundedness | Randomized-pilot consistency (detection rate 0.920 against a strong hidden confounder); placebo, random common cause and subset stability; E-value sensitivity | Cannot be proven. Weak confounding is not detected. Without a randomized slice there is no check at all |
| 3. Positivity | Propensity mass outside `[0.05, 0.95]`, weighted SMD per covariate, Kish effective sample size — a hard refusal, not a warning. Per-customer abstention at scoring time | The bounds are a judgement call; a campaign just inside them still extrapolates somewhat |
| 4. SUTVA | Nothing | Assumed. A word-of-mouth or capacity effect between customers would break it silently |
| 5. Independence | Nothing | Assumed |

**The trade-off, in one sentence:** declaring the DAG buys a refusal when the effect is not
identified, a named open path when it is not, and an adjustment set you did not choose to suit the
answer — and it costs you the honest admission that if the DAG is wrong, everything downstream is
wrong and only the randomized pilot would notice.

## Training data

- **Source:** a seeded structural causal model, `src/double_ml_uplift/causal/scm.py`, configured by
  the YAML files in `src/double_ml_uplift/configs/scenarios/`. Six scenarios: `linear`,
  `nonlinear`, `heterogeneous`, `weak_overlap`, `hidden_confounder`, `randomized`.
- **Why simulated:** both potential outcomes are known, so every estimator can be scored against
  the truth. That is the whole point of the repository and it is not possible with real data.
- **Fingerprint:** each scenario's parameters hash into `ScmConfig.sha256()`, recorded with every
  run. The generator is deterministic in `(parameters, seed)`.
- **Contract:** a pandera schema derived from the causal specification
  (`src/double_ml_uplift/ml/contracts.py`). `strict=True`, so an undeclared column is rejected
  rather than carried into an estimator.
- **Known gaps:** six covariates, one binary treatment, one continuous outcome, one time point,
  one synthetic binary protected attribute. No missing data, no measurement error, no seasonality,
  no interference, no categorical covariates with many levels.

**Exact differential.** `tests/unit/test_estimators.py::test_dml_without_crossfitting_equals_the_ols_coefficient`
asserts that partialling-out DML with OLS nuisances and cross-fitting disabled equals the
statsmodels OLS treatment coefficient to 1e-8 (Frisch–Waugh–Lovell).

**Slices.** Effect heterogeneity is the point, not a slice: in the `heterogeneous` scenario a
sizeable minority of customers have a genuinely negative effect, and the value of uplift targeting
comes entirely from not contacting them. Allocation is checked across the synthetic protected
attribute (see Ethical considerations).

## Robustness and adversarial tests

- **Positivity violation:** `weak_overlap` tilts the historical targeting rule towards
  determinism. The gate refuses 100% of draws; with the gate disabled, AIPW's bias triples and
  IPW's RMSE goes to 12.
- **Nuisance misspecification:** the `nonlinear` scenario makes the outcome and treatment
  mechanisms nonlinear. AIPW and DML keep their coverage; outcome regression's collapses to 0.020.
- **Unmeasured confounding:** `hidden_confounder` adds a latent common cause. Every gate passes
  and the estimate is off by about +64 on average; the randomized-pilot refuter flags it 92% of
  the time.
- **Placebo treatment:** permuting the treatment should collapse the estimate to zero.
  False-flag rate 0.000 on a well-specified scenario;
  `tests/unit/test_refutation.py::test_a_placebo_treatment_catches_a_pipeline_that_ignores_the_treatment`
  shows it catching a pipeline that ignores the treatment entirely.
- **Leakage:** `tests/unit/test_identification.py` refuses mediators, colliders, descendants of
  the outcome, forbidden columns, post-treatment-looking names, and — via `model_construct` —
  specifications whose declared roles were never validated.
- **Ground-truth leakage:** `tests/unit/test_ml_contracts.py::test_every_oracle_column_is_refused_by_name`.
- **Artifact tampering:** `tests/unit/test_bundle.py::test_a_bundle_on_disk_with_a_tampered_artifact_is_refused`.
- **Property-based invariants:** d-separation against brute force, identification soundness,
  minimality and completeness against subset enumeration, fold purity, estimator equivariance,
  budget and fairness bounds.

## Drift and monitoring

- **`uplift_propensity_psi`** — Population Stability Index of the scoring population's propensity
  against a capped, down-sampled vector of training propensities carried in the bundle. The most
  useful single signal here: it moves as soon as the mix of customers being scored stops looking
  like the mix the effect was estimated on. Alert above 0.2.
- **`uplift_abstentions_total`** — customers refused a score because their propensity fell outside
  the overlap region. A rising rate means the model is being asked about a population it was never
  fitted on.
- **`uplift_refusals_total{reason}`** — by cause. A rising `positivity` rate means the historical
  targeting policy has become deterministic and the observational data can no longer answer the
  question at all.
- **`uplift_recommended_treatment_rate`** — share of the last batch the model would target. A
  silent jump is how a broken CATE model shows up before anyone reads a dashboard.
- **`uplift_estimates_total{estimator}`**, **`uplift_exports_total`**, **`uplift_scored_total`**.
- **Retraining trigger:** PSI above 0.2 sustained, an abstention rate above a few percent, or any
  change to the causal specification (its SHA-256 is recorded, so this is detectable rather than
  a matter of memory).

## Ethical considerations

- **Who is affected.** The output decides who is contacted by a retention campaign. Being left out
  is usually harmless; being contacted can be unwelcome, and the `heterogeneous` scenario encodes
  exactly that — for a sizeable minority the offer *reduces* retained revenue. An uplift model is
  the right tool partly because it can decline to contact those customers.
- **Allocation fairness.** The simulator includes a synthetic binary protected attribute, and a
  targeting list whose selection rates differ between the groups by more than
  `APP_FAIRNESS_MAX_DISPARITY` (default 0.15) is blocked before release, with the block written to
  the audit chain. This is **demographic parity on one binary attribute** — one definition among
  several, and it says nothing about intersectional disparity or about whether the underlying
  effect estimates are equally accurate in both groups.
- **Privacy.** Customer ids appear only as `cid_<40 hex>` = HMAC-SHA256(pepper, id). The service
  refuses to start without a pepper. Aggregates below `APP_MIN_COHORT_SIZE` are refused. Bundles
  keep model parameters and a capped propensity sample, not the training data.
- **Automation.** Releasing a list requires a second operator's approval bound to the exact
  payload. The system is designed so that no list of real people leaves it without a named human
  agreeing to that exact list.

## Caveats and recommendations

- **Run a randomized holdout.** It is the only thing in this system that can detect unobserved
  confounding, the only assumption that cannot be checked from the data. Without one, the
  `pilot_consistency` refuter silently skips and the E-value is all that remains.
- **Read the refusals as information, not as an obstacle.** "Not estimable" means the historical
  data cannot answer the question; the fix is an experiment, not a different estimator.
- **Do not read a per-customer uplift as that customer's effect.** No data ever reveals an
  individual effect. The interval attached to a score is the average effect in the decile of
  customers with similar predictions — which is what a targeting decision actually needs.
- **Do not quote the `outcome_regression` interval.** It is shipped to show what a plug-in
  pipeline would report, and its coverage is 0.02–0.46.
- **Re-estimate after any change to the specification.** A stored bundle records the spec hash it
  came from, so reuse under a different specification is detectable.
- **This model has never seen real data.** Every number here is from simulation. Treat it as
  evidence that the estimators and gates work as described, not as evidence about any real
  campaign.
